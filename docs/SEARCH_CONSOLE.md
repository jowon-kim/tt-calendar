# 구글 서치 콘솔 등록 (2026-10-26)

구글이 TT의 공개 페이지(소개·계산기·비교, 9개 언어)를 빨리, 빠짐없이 읽게 하려는 것입니다.
사장님 구글 계정으로 한 번만 하면 됩니다. 15분쯤 걸립니다.

## 1. 사장님이 할 일 — 속성 만들고 태그 받기

1. https://search.google.com/search-console 에 사장님 구글 계정으로 들어갑니다
2. **속성 추가 → 오른쪽 "URL 접두어"** 를 고르고 `https://tt-calendar.vercel.app/` 를 넣습니다
   - 왼쪽 "도메인"은 DNS를 고쳐야 하는데 `vercel.app`은 우리 도메인이 아니라서 못 씁니다
3. 확인 방법 중 **"HTML 태그"** 를 펼치면 이런 줄이 나옵니다

   ```html
   <meta name="google-site-verification" content="긴글자" />
   ```

4. 이 줄을 통째로 Claude에게 넘깁니다. **아직 "확인" 버튼은 누르지 않습니다** — 태그가 배포된 뒤에 누릅니다

이 태그는 비밀값이 아닙니다. 사이트에 걸리면 누구나 볼 수 있는 값이라 공개 레포에 올려도 됩니다.
(비밀값은 서치 콘솔에 로그인하는 사장님 계정 쪽입니다.)

## 2. Claude가 할 일 — 태그 넣고 배포

`public/index.html` 머리에 자리를 만들어 두었습니다.

```html
<!-- 구글 서치 콘솔 확인 태그 자리 — 받은 줄을 이 주석 바로 아래에 그대로 붙입니다. docs/SEARCH_CONSOLE.md -->
```

1. 받은 줄을 그 주석 바로 아래에 붙입니다 (`/` 페이지 하나에만 있으면 됩니다. 소개 페이지에는 안 넣어도 돼요)
2. `npm test` 통과 확인 → main에 푸시 → Vercel이 배포합니다
3. 배포된 주소의 소스에 그 줄이 보이는지 확인합니다 (`view-source:https://tt-calendar.vercel.app/`)

## 3. 사장님이 할 일 — 확인 누르고 사이트맵 내기

1. 서치 콘솔로 돌아가 **확인**을 누릅니다
2. 왼쪽 **Sitemaps** → `sitemap.xml` 입력 → 제출. 주소 28개가 잡히면 됩니다
3. (선택) **URL 검사**에 `https://tt-calendar.vercel.app/en/` 을 넣고 "색인 생성 요청"
4. (선택) 빙 웹마스터 도구(https://www.bing.com/webmasters)에서 "Google Search Console에서 가져오기"를
   누르면 빙도 따로 확인할 필요가 없습니다

색인은 며칠~몇 주 걸립니다. 그 사이 "발견됨 – 현재 색인이 생성되지 않음"은 정상입니다.

**확인 태그는 지우지 않습니다.** 지우면 구글이 다시 확인하다 실패해서 속성 권한이 풀립니다.

## 주소가 맞는지 — 자동 검사

`npm test` 맨 끝의 `node landing.mjs --check`가 푸시마다 확인합니다.

- `sitemap.xml`의 주소 28개가 모두 `https://tt-calendar.vercel.app/` 아래이고, 실제 파일이 있는지
- `robots.txt`가 같은 사이트의 `sitemap.xml`을 가리키는지 (`/api/`만 막음)
- 페이지마다 `canonical`·`og:url`이 sitemap에 적힌 자기 주소와 같은지
- hreflang이 자기 자신을 포함하고, 가리킨 페이지도 되돌려 가리키는지(구글은 한쪽만 가리키면 버립니다),
  가리킨 주소가 모두 sitemap에 있는지

2026-10-26 점검 결과: 소개·계산기·비교 27쪽은 맞았고, 앱 첫 화면(`/`)만 틀렸습니다. 소개 페이지 9개를
hreflang으로 가리키는데 그쪽은 `/`를 되돌려 가리키지 않아서 구글이 무시하는 상태였습니다. `/`는 소개 페이지의
번역이 아니라 앱 화면이라, 그 줄들을 빼고 위의 검사를 붙였습니다.

클라우드 세션에서는 실제 사이트(`tt-calendar.vercel.app`)에 접속이 막혀 있어서, 배포된 파일이 레포와
같은지는 확인하지 못했습니다. 레포 파일 기준으로만 검사했습니다.

## 도메인을 바꾸면

1. `landing.mjs`의 `SITE` 한 줄을 고치고 `npm run landing`
2. `public/index.html` 머리의 `canonical`·`og:url`·`og:image` 주소를 고칩니다 — 빠뜨리면 `npm test`가 실패합니다
3. 서치 콘솔에 새 주소로 속성을 하나 더 만들고(1~3절 다시), 옛 속성에서 **주소 변경** 도구를 씁니다
